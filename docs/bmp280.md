# BMP280 configuration layer

`Systems.Sensing.Barometer.Device` composes independent `physics` and
`vendorConfig` components. Its defaults preserve B0 through a pass-through
vendor stage. Select BMP280 explicitly:

```modelica
Systems.Sensing.Barometer.Device barometer(
  redeclare model VendorConfigModel=
    Systems.Sensing.Barometer.VendorConfig.BMP280);
```

Bind the ordinary ambient pressure, temperature, altitude and climb-rate inputs
to the device, and the three command inputs to its vendor stage. Existing B0,
B1 and other sensor paths are unchanged. BMP280 accepts only continuous B0
measurements; sampled physics is rejected to prevent two acquisition clocks.
The vendor receives measured pressure [Pa], temperature [K] and their timing,
without truth, mounting or bias inputs. Geometric altitude and climb rate pass
directly from physics; the chip does not report them.

## Implemented bench envelope

The layer starts after power-on reset has settled: asleep, CTRL_MEAS and CONFIG
zero, pressure and temperature registers containing `0x80000`, and no valid
measurement. Normal mode uses temperature oversampling x2, pressure x16,
37.5 ms conversion and 0.5 ms standby. These are representative typical timings,
not guaranteed silicon periods; the documented conversion maximum is 43.2 ms.

At conversion start, measured Pa/K are captured and converted to ideal raw ADC
counts. At completion, the configured IIR filter updates both raw channels;
the resulting counts are rounded to unsigned 20-bit register values and held.
Reads do not acquire or filter again. `sampleTime` records conversion start,
`deliveryTime` completion, and `sequence` counts completed measurements.
`valid` is false before the first completion. Exact bench expectations require
inputs held through each conversion; within-conversion averaging is unmodeled.

The IIR coefficient is off, 2, 4, 8 or 16. Each update is
`filtered = (previous * (coefficient - 1) + raw) / coefficient`.
An accepted CONFIG write resets filter memory, including an identical write;
the next completed measurement seeds it. Filter memory uses real arithmetic
and register output uses nearest-integer rounding. The manual does not specify
internal fractional precision or rounding, so this is an explicit approximation.
The 20-bit register format is not an ADC accuracy claim: oversampling-dependent
ADC resolution and noise are unmodeled, including temperature's x2 resolution.

One immutable **synthetic calibration-ROM fixture** makes the arithmetic
independently checkable: T1=T2=P1=P9=16384, other trim coefficients zero.
It is neither measured factory calibration nor a manufacturer example. With
this fixture, temperature counts are `262144 + 5120 * temperature_C`. Pressure
compensation is `P = b + b*b/2097152`, where
`b = (1048576 - pressure_count) * 6250/16384`; the model inverts that expression
before filtering. Its supported input range is 30000..110000 Pa and 0..65 C.
Real-device calibration, ADC noise and electronic accuracy are not qualified.

## Writes and readback

Inputs `commandSequence`, `commandRegister` and `commandValue` represent one
delivered register write. IDs must increase monotonically; zero means no write
yet. Process each write and observe its completion before sending the next.
`processedCommandSequence` identifies the completed request. `commandStatus` is
an emulator diagnostic: 0 idle, 1 applied, 2 ignored by the selected normal-mode
policy, 3 unsupported coverage. These values are not chip ACK/NAK responses.

| Register | Supported behavior |
| --- | --- |
| ID 0xD0 | Read 0x58 |
| Calibration 0x88..0x9F | The same immutable 12-word fixture used by the model, little endian; T1/P1 unsigned, other words signed |
| CTRL_MEAS 0xF4 | Write 0 or 0x54 for sleep, 0x57 for normal x2/x16; same-value writes preserve acquisition timing |
| CONFIG 0xF5 | Filter bits only; codes 0..7 select off/2/4/8/16/16/16/16, with 0.5 ms standby |
| Data 0xF7..0xFC | One coherent pressure/temperature snapshot; each count occupies the high 20 bits of its three-byte field |

`ctrlMeas`, `config`, `rawPressure`, `rawTemperature`, `chipId` and `calibration`
are the Modelica-owned values used by the thin bench codec. The codec keeps no
second authoritative configuration or filter state. `converting` is a bench
diagnostic, not a complete implementation of the STATUS register.

Sleep CONFIG writes are accepted. In normal mode, the fixed per-run parameter
`normalModeConfigWritesAccepted` selects acceptance or ignoring. This parameter
expresses two experimental outcomes allowed by the manual's conditional rule;
it is **not a real sensor configuration setting or a measured silicon policy**.
Under the ignore policy, configuration and filter memory are preserved.

Timer transitions precede writes at the same simulation time. This slice supports
mode changes during standby only. A busy mode change, forced mode, other
oversampling/standby settings, SPI3W, reset and unmodeled register accesses are
coverage gaps. Actual busy-mode deferral and reset/NVM-copy timing require a
later increment. Unsupported requests must not be presented as device NAKs or
successful operations.

## Native-driver harness

Run `FIRE_TEST_BMP280=1 python -m unittest tools.test_bmp280` with OpenModelica
and its bundled compiler available. The harness exports a sensor-only FMI2
co-simulation model and compiles unchanged ArduPilot BMP280, checked-register
and barometer-backend source against a small test HAL/frontend. Bus transactions
cross the Modelica boundary; C++ only packs and transfers bytes.

The sensor bench advances through positive 10 us transaction-service intervals.
Command application is bounded by that interval; this is a numerical bench
policy, not physical I2C timing. OpenModelica's zero-state co-simulation FMU
handles events at the start of a host step. The harness therefore exports
internal variables with `--fmiFilter=internal`, reads Modelica's own
`nextTransition` deadline, and splits steps there. A positive 1 ps step services
an event at that deadline; observations may cross it by that numerical epsilon.
No second acquisition clock is calculated in Python or C++.
This specialized local-variable access is not a portable public sensor ABI.
It does not advance an aircraft simulation or establish general synchronous
SITL bus support. The first native read can precede
the first conversion and see reset counts; the adapter does not conceal them.

A retained-setting scenario first writes filter16 while asleep, enters normal
mode, and completes acquisitions before starting the native host. Host restart
preserves the sensor FMU, clock and command IDs. Cold controls use separate
initialized instances; live power/reset transitions are not modeled. The actual driver requests filter4 after normal
mode and checks mismatches; an accepting write repairs them. An ignored write
can leave the prior filter in place despite retries. Exact constant readings
still encounter the ordinary two-second changed-data health check.

This implementation's boundary is the ordered sensor/native-driver bench.
It does not establish hardware write acceptance, a complete BMP280, full native
SITL startup, prearm/estimator behavior or a flight defect. Pressure-only SITL
injection bypasses the BMP280 driver and is not changed here.

## Evidence

Bosch BMP280 BST-BMP280-DS001-26 revision1.26, October2021:
[manufacturer manual](https://www.bosch-sensortec.com/media/boschsensortec/downloads/datasheets/bst-bmp280-ds001.pdf),
sections3.3.3 (raw IIR, pp13-14),3.6 (modes),3.8 (timing, pp18-19),
4.2-4.3 (registers, pp24-26), and appendix8.1 (compensation).
The filter-code mapping omitted from revision1.26 Table6 is given explicitly
in the manufacturer-authored revision1.13 Table6, available from this
[distributor mirror](https://dfimg.dfrobot.com/wiki/17649/SEN0226_i2c-bmp280-barometer-sensor_datasheet_V1.0.pdf).

The native bench targets ArduPilot
`1ebd4d996e8b6bbeb1462a9655c00aa861d5beef` (Copter4.6.2).
The same configuration ordering was separately inspected at upstream
`edd21074565af72cc993bfb3921862e49f880c8c`; this is source comparison, not
upstream execution. The closest active FIRE barometer is the continuous ideal
model at `2b7b3a35983777988b66bbacf90c91bdda72f311`; it has no chip/register stage.
Audit BAR-01 (CFG0036, merged0037/0038) suggests the retained-filter experiment
but does not establish a practical defect. No hardware witness is available.
